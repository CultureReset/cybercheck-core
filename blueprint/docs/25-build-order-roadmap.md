# Build Order and Roadmap

The correct sequence stabilizes shared contracts and truth before multiplying products and executors.

## Source-grounded rules
- Canonical schema comes before publisher-specific adapters.
- Connector normalization comes before advanced agents.
- Core read/write paths and permissions come before exposing broad MCP/action surfaces.
- Builder/Runner and device/browser complexity comes after capability/orchestrator contracts exist.

## This subsystem owns
- milestone sequencing
- dependency gates
- acceptance demos

## Core objects / data
- `milestone`
- `dependency`
- `acceptance_test`

## Main flow

```text
1 Contracts
2 Identity + Core
3 Canonical data
4 Research + verification
5 Connectors + normalization
6 Streams/projections + search
7 Gateway + permissions
8 Marketplace/installations
9 Orchestrator + ledger
10 Browser/device/compute runtimes
11 Builder → Runner
12 Independent products + developer ecosystem
```

## UI / UX surfaces
- Roadmap dashboard
- Milestone checklist
- Dependency map
- Acceptance demo tracker

## Required states and failures
- Downstream team starts before contract stable
- Legacy dual-write persists too long
- Runtime work races ahead of policy
- Too many products before first vertical slice

## Definition of done
- [ ] Each milestone has a working acceptance demo
- [ ] First vertical slice passes before broad product rollout
- [ ] Legacy retirement is scheduled, not indefinite
